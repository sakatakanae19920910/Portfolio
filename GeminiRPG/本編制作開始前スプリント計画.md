### 4. GameData.cs の設計見直し

**目的**: 現在の static 変数の寄せ集めをセーブ/ロードに耐えられる設計に直す

**現状の問題**:
- `GameData` は static クラスで、ゲーム中のデータを全部持っている
- Phase 2 でセーブ/ロードを実装する時に「後から足す」のが一番つらい
- デモ専用変数（MitamaCount等）と本編変数が混在している

**方針案（要相談）**:
- `SaveData` クラス（セーブに含める変数）と `RuntimeData` クラス（セッション中のみ必要な変数）に分離
- `SaveData` はシリアライズ可能な構造体にしておく（JsonUtility対応）
- `GameData` は `SaveData` と `RuntimeData` の両方を持つ管理クラスに

### 5. ScenarioExecutor.cs リファクタリング

**目的**: イベント後に先送りにしていたコード整理。本編でシナリオコマンドが増える前にやる

**現状の問題**:
- コマンド処理が1つの巨大な switch-case に詰まっている
- デモ制作中に追加したコマンドがインラインで増え続けた
- `HandleText`/`HandleMonologue` など似た処理が重複している

**やること**:
- コマンドハンドラーをメソッドに切り出し（1コマンド=1メソッド）
- `HandleText` / `HandleMonologue` を統合
- 孤立したコメントや未使用フィールドの削除
- **逆写経の良い素材になる** → リファクタ後に全コメントを書き直す

### 6. パーティクル問題を解決・理解する

**目的**: Phase 1 のバトルエフェクトに備えて、URP 2D でパーティクルを動かす方法を習得する

**現状**: URP 2D Renderer でパーティクルが Game view に出ない（Scene view には出る）
- 原因: URP 2D Renderer がデフォルトで Particle System を描画しない
- 解決策: Renderer2D に `Render Objects` Renderer Feature を追加する

**やること**:
- シェーダーを `Universal Render Pipeline/Particles/Unlit` に設定
- `Renderer2D` に `Render Objects` を `AfterRenderingTransparents` + `Everything` で追加
- ミタマ石でテスト → 動いたら本番の色・サイズに調整
- 理解を確認: 「なぜこの設定が必要なのか」を自分の言葉で説明できるようにする

### 10. デモ版の英語ローカライズ

**目的**: 海外からのウィッシュリスト獲得を早期に狙う。広報戦略方針⑤「英語フル対応は発売時確定」の先行として、まずデモの英語対応から始める。

**対象範囲（デモ版のみ）**:
- シナリオCSV（`Assets/Resources/Scenario/Demo/`）のテキスト列を英語翻訳
- UI文字列（ボタンテキスト・メニュー等）
- タイトル画面・DemoEnd画面のテキスト

**方針**:
- Unityのローカライズパッケージは**使わない**（本編実装前に複雑化させない）
- CSVに `text_ja` / `text_en` の2列を持たせ、`ScenarioExecutor` で言語設定に応じて切り替える簡易対応
- 言語切り替えUIは最小限（タイトル画面にJP/ENボタン1つ）
- 翻訳はClaude Codeが下訳 → kanaeが確認・調整

**注意**:
- Steam公式の「対応言語（Supported Languages）」欄への英語登録は、本実装完了後に行う（広報戦略方針⑤）
- デモが日本語のみの間はSteamページ本文に `The demo is currently Japanese only.` を残す → 英語対応完了後に削除

**完了条件**:
- [ ] デモシナリオ全文の英訳完了・動作確認
- [ ] タイトル画面にJP/EN切り替えが機能している
- [ ] Steamページの言語注記を更新済み
