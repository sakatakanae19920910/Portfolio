# マップ通行設定完全マニュアル

**作成日**: 2026-05-13  
**対象**: TownScene・PartnerHouse1FScene など歩行可能なマップシーン全般

---

## このマニュアルでわかること

- 壁や障害物をプレイヤーが通り抜けないようにする方法
- どのタイルをどのレイヤーに置くべきかの判断基準
- プレイヤーの当たり判定サイズの調整方法
- カウンター越し・水面など特殊なケースの対処法
- 通行設定が効かないときのデバッグ方法

---

## 1. この仕組みの全体像

```
プレイヤー（Rigidbody2D + CapsuleCollider2D）
      ↕ 衝突する
コライダーを持つ Tilemap（TilemapCollider2D + CompositeCollider2D）
```

コライダーを持つ Tilemap が「壁」として機能する。**どのレイヤーにコライダーをつけるか**は2種類の方式があり、マップの種類で使い分ける。

---

## 1-A. 各コンポーネントの役割

通行設定に登場するコンポーネントは5種類。それぞれ担当が異なる。

### タイルマップ側（壁・障害物）

| コンポーネント            | 誰につける             | 役割                                                                                                                                              |
| ------------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| **TilemapCollider2D**     | Collision / 壁レイヤー | タイル1枚ずつに当たり判定を生成する。これ単体でも機能するが、タイル数が多いと重い                                                                 |
| **CompositeCollider2D**   | Collision / 壁レイヤー | 隣接するタイルの当たり判定を1つの形にまとめる。処理が軽くなり、壁の隙間への引っかかりも防ぐ                                                       |
| **Rigidbody2D（Static）** | Collision / 壁レイヤー | CompositeCollider2D を使うために必須。Static にすることで「動かない物体」として物理演算に登録される。壁が動いたり落下したりしないのはこれのおかげ |

> **TilemapCollider2D だけでも壁になる**が、CompositeCollider2D とセットで使うのが正解。単体だとタイルとタイルの境目に微妙な隙間が生まれてプレイヤーが引っかかる。

### プレイヤー側

| コンポーネント             | 誰につける | 役割                                                                                                                                |
| -------------------------- | ---------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| **CapsuleCollider2D**      | Player     | プレイヤーの当たり判定の「形」を定義する。カプセル形（上下が丸い）なので壁の角に引っかかりにくい                                    |
| **Rigidbody2D（Dynamic）** | Player     | プレイヤーを物理演算に登録する。これがあることで TilemapCollider2D と衝突できる。Dynamic にすることでコードから速度を与えて動かせる |

### なぜ Rigidbody2D が両方に必要なのか

Unity の物理衝突は **「Rigidbody2D を持つもの同士」** または **「Rigidbody2D と Collider2D」** の間で起きる。

```
Player（Rigidbody2D Dynamic + CapsuleCollider2D）
    ↕ Rigidbody2D があるから衝突できる
壁 Tilemap（Rigidbody2D Static + TilemapCollider2D + CompositeCollider2D）
```

Tilemap 側の Rigidbody2D を Static にするのは「衝突は受け付けるが自分は動かない」という意味。

## 1-B. 方式の選び方

| 方式                          | 概要                                             | 向いてる場面                                           |
| ----------------------------- | ------------------------------------------------ | ------------------------------------------------------ |
| **視覚レイヤー直接方式**      | Buildings など壁レイヤーに直接コライダーをつける | **内装マップ**・小さいマップ（壁タイル全部が通行不可） |
| **Collisionレイヤー分離方式** | 別途 Collision レイヤーを作る                    | **屋外マップ**・地面の一部だけ通行不可にしたい場合     |

### 視覚レイヤー直接方式（例: PartnerHouse1FScene）

```
Buildings レイヤー（壁タイル）
  + TilemapCollider2D
  + Rigidbody2D (Static)
  + CompositeCollider2D
```

内装は「壁レイヤーのタイル = 全部通行不可」が成立するのでシンプルで正解。

### Collisionレイヤー分離方式（例: TownScene）

```
Buildings レイヤー（見た目のみ）← コライダーなし
Collision レイヤー（透明・非表示）← コライダーあり
```

屋外マップは同じ視覚タイルでも「通れる場所」と「通れない場所」が混在するため、分離した方が管理しやすい。

> **現在の設定を確認したい場合**: Hierarchy でレイヤーオブジェクトを選択 → Inspector に TilemapCollider2D があればそのレイヤーが壁として機能している。

---

### このプロジェクトの標準レイヤー構成

| レイヤー      | 役割               | 物理判定                   |
| ------------- | ------------------ | -------------------------- |
| Ground        | 地面・草           | なし                       |
| Path          | 道・広場           | なし                       |
| Buildings     | 建物の壁・床       | なし（見た目のみ）         |
| Objects       | 木・岩・家具・装飾 | なし                       |
| Rooftop       | 屋根               | なし                       |
| **Collision** | **通行不可エリア** | **あり（コリジョン専用）** |

## 2. Collision レイヤーのセットアップ（新シーン作成時）

> **既にセットアップ済みのシーンには不要**。TownScene を複製した場合もスキップ可。

### 2-1. Collision タイルマップに必要なコンポーネント

`Collision` オブジェクトを選択 → Inspector で以下を確認・追加する。

| コンポーネント          | 設定内容                                       |
| ----------------------- | ---------------------------------------------- |
| **Tilemap Renderer**    | チェックを**オフ**（Game view で非表示にする） |
| **TilemapCollider2D**   | Used By Composite: **オン**                    |
| **Rigidbody2D**         | Body Type: **Static**                          |
| **CompositeCollider2D** | Geometry Type: **Polygons**（デフォルト）      |

追加の順番（順番どおりにやること）:

```
1. Tilemap Renderer のチェックをオフ
2. Add Component → TilemapCollider2D
3. Add Component → Rigidbody2D → Body Type を Static に変更
4. Add Component → CompositeCollider2D
5. TilemapCollider2D の「Used By Composite」にチェック
```

> **CompositeCollider2D を使う理由**: タイル1枚ずつに判定が生まれると処理が重い。Composite を使うと隣接するタイルの判定がひとつの形にまとまり、パフォーマンスが上がる。また壁の隙間にプレイヤーが引っかかる問題も防げる。

## 3. Collision タイルの配置方法

### 3-1. コリジョン用タイルを用意する

専用の「コリジョンタイル」は1種類あればよい。見えないタイルなので外見は何でもよい。

**推奨: 既存タイルセットから単色・単純なタイルを1枚流用する。**

Project ウィンドウ → Tile Palette → Collision レイヤーを選択した状態で塗る。

### 3-2. 何のタイルを塗るべきか

下の表を判断基準にする。

| タイルの種類               | Collision を置く？ | 補足                                         |
| -------------------------- | ------------------ | -------------------------------------------- |
| 建物の外壁                 | ✅ 置く             | 全面に塗る                                   |
| 岩・大木                   | ✅ 置く             | 全面に塗る                                   |
| 水・溶岩                   | ✅ 置く             | 全面に塗る                                   |
| カウンター（対面型）       | ✅ 置く             | プレイヤーが乗れないよう全面                 |
| テーブル・椅子             | ✅ 置く             |                                              |
| 地面・道                   | ❌ 置かない         | 歩けるエリア                                 |
| ドアの前（通過できる場所） | ❌ 置かない         | MapTransitionで別途処理                      |
| NPC                        | ❌ 置かない         | NPCTriggerのBoxCollider2D(IsTrigger)で別処理 |

### 3-3. 塗り方の手順

1. Hierarchy で **Collision** タイルマップを選択
2. **Window > 2D > Tile Palette** を開く
3. Active Tilemap に **Collision** が選択されていることを確認
4. ブラシツールでコリジョンを置きたい場所を塗る（建物の壁に重ねて塗る）

> **Visual Layer と Collision Layer で同じ座標に塗る**。Buildings レイヤーに壁がある位置に、Collision レイヤーでも同じ座標を塗る。

## 4. プレイヤーの CapsuleCollider2D 調整

プレイヤーの当たり判定は足元（下半身）だけにするのが標準的なRPGの設定。

### 4-1. このプロジェクトの標準値

このプロジェクトはキャラチップが **96px × 96px**、PPU = **48** のため:

- キャラクターは視覚的に **2ユニット × 2ユニット**
- 1タイル = **1ユニット**（48px）

CapsuleCollider2D の推奨設定:

| 設定項目           | 推奨値   | 説明                       |
| ------------------ | -------- | -------------------------- |
| **Direction**      | Vertical | 縦長のカプセル形           |
| **Size X**（幅）   | `0.6`    | キャラの横幅より少し小さく |
| **Size Y**（高さ） | `1.0`    | 足元～腰あたりまで         |
| **Offset Y**       | `-0.5`   | 下にずらして足元に合わせる |

### 4-2. 調整手順

1. Hierarchy で **Player** を選択
2. Inspector の **CapsuleCollider2D** を確認
3. **Scene view でコライダーの緑の枠を確認しながら調整**（再生しなくても見える）
4. キャラクターの足元の半分くらいを覆う大きさが理想

> **細かすぎると壁をすり抜ける**。**大きすぎると壁に当たる前に止まって窮屈**に見える。0.6 × 1.0 から始めて見た目で調整する。

### 4-3. Scene view でコライダーを確認する方法

Scene view 上部の **「Gizmos」ボタン** → **「Physics 2D」** にチェックが入っていれば緑の枠が表示される。再生しなくても確認できる。

## 5. 特殊なケース

### 5-1. カウンター越しに話しかけられる設定

ショップのカウンターなど、「通れないけど話しかけられる」設定。

```
Collision:  [カウンタータイル] ← プレイヤーが通れない
NPC:        BoxCollider2D (Is Trigger: オン)  ← 話しかけられる（当たり判定は Trigger）
```

- カウンターには Collision タイルを置く（通行不可）
- NPCの BoxCollider2D は **Is Trigger: オン** にする
- Trigger の判定範囲をカウンターの手前に広げる（Size を大きくする）

### 5-2. ドアの通過設定

ドアはシーン遷移（MapTransition）で処理する。コリジョンタイルは置かない。

```
ドア位置: Collision なし（歩いて通過できる）
MapTransition オブジェクト: BoxCollider2D (Is Trigger) + MapTransition.cs
```

詳細: [新シーンマップ作成マニュアル.md > Step 8](新シーンマップ作成マニュアル.md)

### 5-3. 大きいスプライトを重ねて配置する（木・岩など）

タイルのスプライト領域（透明部分を含む四角）が後ろのタイルを隠すため、同じレイヤーに重ねると木が切れて見える。

**解決策：オブジェクトレイヤーを2つに分ける**

| レイヤー | Sorting Order            | 用途                         |
| -------- | ------------------------ | ---------------------------- |
| Objects  | 3                        | 通常の木・岩                 |
| Objects2 | 4（Rooftopより低く設定） | 前に出したい木・重ねたい装飾 |

重ねて配置したいときは **手前に見せたいタイルを Objects2 に置く**だけでOK。Y-sortやPivot調整は不要。

> Y-sortやIndividualモードよりシンプルで確実。デモ規模ではこの方式が最適。

### 5-4. 下を潜れるタイル（木・アーチ・軒など）

「潜る」は3Dではなく**描画順（Sorting Order）の制御**で実現する。プレイヤーより高い Sorting Order のタイルがプレイヤーの上に重なって見えることで、潜っているように見える。

#### 描画順の基本

```
Rooftop レイヤー（Sorting Order 4）← プレイヤーより手前 → 潜って見える
Player  Sprite Renderer（Order in Layer: 3）
Objects レイヤー（Sorting Order 3）
Buildings レイヤー（Sorting Order 2）
Ground レイヤー（Sorting Order 0）
```

#### 設定手順

**① Player の Sprite Renderer → Order in Layer を `3` に設定する**

Hierarchy で Player を選択 → Sprite Renderer → **Order in Layer: `3`**

**② タイルを上下に分割して配置する**

| 部位                 | 置くレイヤー                       | コリジョン | 例                           |
| -------------------- | ---------------------------------- | ---------- | ---------------------------- |
| 上部（潜れる部分）   | **Rooftop**（Sorting Order 4）     | なし       | 葉っぱ・屋根の軒・アーチ上部 |
| 下部（通れない部分） | **Collision** または **Buildings** | あり       | 幹・柱・壁の根元             |

#### 具体例：木

```
Rooftop 層  → 🌿 葉っぱタイル（コリジョンなし）
Objects 層  → 🪵 幹タイル（見た目）
Collision 層 → ▪ 幹タイル（通行不可）
```

プレイヤーが幹の横を通ると葉っぱがプレイヤーの上に重なり、木の下を潜っているように見える。

#### 具体例：建物の軒・アーチ

```
Rooftop 層   → 軒・アーチの上部タイル（コリジョンなし）
Buildings 層 → 軒・アーチの壁部分（コリジョンあり）
```

入口の上部のアーチだけ Rooftop に置くと、プレイヤーがアーチをくぐる演出になる。

> **コリジョンは根元だけ置けばよい**。葉っぱや屋根の軒部分にコリジョンを置くと空中の見えない壁になってしまうので注意。

### 5-4. 屋根・天井の通行（屋外→屋内の切り替え）

現在のデモでは屋根の下のエリアに直接移動しない設計（シーン切り替え方式）のため、特殊な通行設定は不要。

## 6. Physics Layer Matrix の設定（オプション・パフォーマンス改善）

デフォルト設定でも動くが、コライダーが多くなった場合はレイヤーを設定すると処理が軽くなる。

**Edit > Project Settings > Physics 2D > Layer Collision Matrix**

以下のレイヤーを追加し、プレイヤーとコリジョンタイルマップのみが衝突するよう設定する:

| レイヤー名   | 用途                      |
| ------------ | ------------------------- |
| Player       | プレイヤー専用            |
| MapCollision | Collisionタイルマップ専用 |
| NPC          | NPCのTrigger専用          |

> **デモ版制作中はデフォルトLayer設定で問題ない**。NPCが増えてきたり処理が重くなったら対応する。

## 7. デバッグ方法

### 7-1. コライダーを可視化する（再生中）

**Scene view** → 上部 **「Gizmos」** をオン → コライダーが緑の枠で表示される。

再生中でも Scene view を見ながら移動すると、プレイヤーとタイルのコライダーがどこにあるか確認できる。

### 7-2. Collision レイヤーを一時的に表示する

Collision タイルマップの **Tilemap Renderer** を**一時的にオン**にすると、どこにコリジョンタイルが置かれているか可視化できる。確認後は必ずオフに戻す。

手順:
1. Hierarchy で **Collision** を選択
2. Inspector の **Tilemap Renderer** のチェックをオン（一時的に）
3. Scene view / Game view でタイルの配置を確認
4. 確認後チェックをオフに戻す

### 7-3. Console でエラーを確認する

コリジョンが効かない場合に Console に出やすいエラー:

| エラーメッセージ                           | 原因                                                                       |
| ------------------------------------------ | -------------------------------------------------------------------------- |
| `CapsuleCollider2D: Ignoring Rigidbody...` | PlayerのRigidbodyとTilemapのRigidbodyが干渉 → TilemapのRigidbodyをStaticに |
| 壁すり抜けのみで Consoleは静か             | Collision タイルが未配置 or Used By Composite がオフ                       |

## 8. よくある問題と解決策

### ❌ プレイヤーが壁をすり抜ける

```
確認順:
1. Collision レイヤーにタイルが置かれているか
   → Tilemap Renderer を一時的にオンにして確認
2. TilemapCollider2D の「Used By Composite」がオンか
3. CompositeCollider2D が Collision オブジェクトにあるか
4. Player の CapsuleCollider2D が設定されているか
```

### ❌ 壁に当たる前に止まる / 見えない壁がある

```
原因: Collision タイルが余分な場所に置かれている
確認: Tilemap Renderer を一時的にオンにしてタイルの範囲を確認
修正: Tile Palette の消しゴムツールで余分なタイルを削除
```

### ❌ 壁の角に引っかかる

```
原因: CapsuleCollider2D でなく BoxCollider2D を使っている
修正: Player のコライダーを CapsuleCollider2D に変更する
     （BoxCollider2D の角が壁の角に当たって引っかかる）
```

### ❌ Player が床に沈む / 飛ぶ

```
原因: Player の Rigidbody2D の Gravity Scale が 0 以外になっている
確認: Player → Rigidbody2D → Gravity Scale が 0 か確認
```

### ❌ NPC をすり抜ける

```
NPC はわざと通り抜けられる設計（Is Trigger: オン）。
NPC を物理的な壁にしたい場合:
  → BoxCollider2D の Is Trigger をオフにする
  → NPC に Rigidbody2D (Static) を追加する
ただし、デモ版では Is Trigger のままが推奨（NPCが密集するとプレイヤーが詰まるため）
```

## 9. チェックリスト（新マップ完成時の確認）

```
通行設定
  [ ] Collision レイヤーに TilemapCollider2D がある
  [ ] TilemapCollider2D の「Used By Composite」がオン
  [ ] CompositeCollider2D がある
  [ ] Tilemap Renderer がオフ（非表示）になっている
  [ ] 壁・障害物の上に Collision タイルが配置されている
  [ ] 歩行可能エリアに Collision タイルがない

プレイヤー設定
  [ ] CapsuleCollider2D がある（BoxCollider2D ではなく）
  [ ] Direction: Vertical
  [ ] Size X: 0.6 / Size Y: 1.0 あたりに設定されている
  [ ] Rigidbody2D の Gravity Scale が 0

動作確認
  [ ] 全方向の壁に当たって止まる
  [ ] 壁の角に引っかからずスムーズに通れる
  [ ] 歩行エリアを自由に歩ける
  [ ] ドアの位置に Collision タイルがない（通過できる）
```
