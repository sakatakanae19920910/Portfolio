### 作業担当者
Claude Code

### 概要
**A4壁タイルの上下配置挙動を完全修正。** 縦に並べた時に「棚（上端パーツ）」が全段に出てしまう問題と、上下が逆になる問題を段階的に解決した。

### 不具合の内容と修正（わかりやすく）

#### 不具合①「棚が毎段ごとに出てくる」

**何が起きていたか:**
壁を縦に3マス以上並べると、本来は一番上の段にしか出ないはずの棚（装飾のある上端パーツ）が、全部の段に繰り返し出てきてしまっていた。

**原因:**
壁タイルが自分の上下の状況を見て「自分は最上段か・中間か・最下段か」を判断する仕組み（Rule Tile）になっているが、上下の判定条件がなく、常に同じスプライトが使われていた。

**修正内容:**
- タイルが上下の隣接状況に応じてスプライトを切り替えるルールを追加
  - `wall_top_*`（棚つき）→ 上が空っぽ、下に同じ壁がある時だけ使用
  - `wall_body_*`（中間）→ 上下ともに同じ壁がある時
  - `wall_bot_*`（下端）→ 上に同じ壁があり、下が空っぽの時
- **中間段（body）のスプライト合成**: 「行0の下半分24px ＋ 行1の上半分24px」の組み合わせにすることで、上の段と下の段の境界がシームレスに繋がるよう調整

#### 不具合②「上と下のパーツが逆に出る」

**何が起きていたか:**
①の修正後、棚（本来は上端）が一番下の段に表示され、下端パーツが上に出るという上下逆転が発生。

**原因:**
Unityのグリッド座標の方向を誤解していた。「上の隣のセル」を指定するつもりで書いたルールが、実際には「下の隣のセル」を指していた（Y軸の＋方向が視覚的に上か下か混乱していた）。

**修正内容:**
Unity 6の2Dタイルマップは標準座標（Y+ = 画面上方向）。ルールの上下条件値を入れ替えた：
- 壁の最上段 → 「上のセルが異なるタイル、下のセルが同じタイル」という条件が正解
- 誤って逆（上=同じ、下=異なる）になっていたのを修正

#### 不具合③「最下段がシームレスな中間と同じ見た目になる」

**何が起きていたか:**
壁の一番下の段も中間段と同じ合成スプライト（行0下半＋行1上半）になっていて、ちゃんとした下縁テクスチャが出なかった。

**修正内容:**
最下段（`wall_bot_*`）は「行1まるごと」を使うよう変更。これで上端・中間・下端それぞれ異なるテクスチャが正しく表示される。

### 技術詳細

**generate_autotile.py の変更点:**
- `generate_wall_face()` 関数内:
  - `make_body_col()` ヘルパー追加（行0下半24px ＋ 行1上半24px の合成）
  - `bot_mid`, `bot_iso` 変数追加（行1まるごとの下端スプライト）
  - 16スプライト構成（top×4, body×4, bot×4, iso×4）でJSON出力
  - neighbor値を正しい上下条件に修正

**確定した Unity Rule Tile の上下neighbor値:**
| スプライト | T（上のセル） | B（下のセル） |
|---|---|---|
| wall_top（最上段） | 2=NotThis（空/天井） | 1=This（同タイル） |
| wall_body（中間段） | 1=This | 1=This |
| wall_bot（最下段） | 1=This | 2=NotThis（空/床） |
| wall_iso（孤立） | 2=NotThis | 2=NotThis |

### ユーザーが学んだこと
- Rule Tileは「自分の上下左右に何があるか」を見てスプライトを切り替える仕組み。条件を細かく設定するほど状況に応じた見た目になる
- Unityのグリッド座標はY+ = 画面上方向（直感通り）。ツール側のコードのバグで逆に設定されていたのが問題だった

**原因:**  
通常のA2タイルは「48×48を24×24の4分割（クォーター）に切り分けて組み合わせる」方式で31パターンを生成する。しかしスイレンの葉は直径35px程度の丸い絵で、24×24に切ると丸が分断されてバラバラになってしまう。

- `generate_simple_tiles()` 関数を新設: 6枚のソースタイルをそのまま src0〜src5 として出力
- `INSIDE_A1_SIMPLE = {3, 11}` 定数を追加: グループ3（inside_a1_grass）とグループ11（inside_a1_grass_2）をシンプルタイルとして扱うよう設定
- Rule Tile JSONの `output: "random"` + `sprites` 配列を使い、配置時に6バリアントからランダム1枚を選ぶ方式に
- `RuleTileGenerator.cs` を拡張: `output: "random"` の JSON を読んで `OutputSprite.Random` モードの Rule Tile を生成できるよう対応

**何が起きていたか:**

**修正① : ソースのIC_*ピースを直接使う**
- RPG Maker A4ソースの `tile[1]`（内角ピース格納タイル）には、各方向の凹み角スプライトが正確に入っている（IC_TL/TR/BL/BR）

ic_*コンボではINNERとIC_*が隣接するため千切れが発生するが、bitmask 3/6/9/12では隣接クォーターが全て非INNER（フレーム辺ピース）のため千切れが生じない。

| スプライト | 対角条件 | 使うクォーター | 用途 |

**何が起きていたか（初期状態）:**

**1回目の試み（失敗）:**
`_CEIL_T_JUNCTION` を `{}` に設定し、T字タイルのIC_*を全削除。Xフレームは消えたが、今度はL字形状などの本物の内角コーナーも消えてしまった。

**根本解決（2回目）:**
「対角方向が NotThis（空/異タイル）のときのみ IC_* を使う」4バリアントを各T字ビットマスクに生成。

| バリアント | 条件 | 使用スプライト |
|---|---|---|
| `_ab` (例: `_sw_se`) | 対角A=NotThis, 対角B=NotThis | IC_A + IC_B |
| `_a` (例: `_sw`) | 対角A=NotThis | IC_A + INNER |
| `_b` (例: `_se`) | 対角B=NotThis | INNER + IC_B |
| base | don't care | INNER + INNER（ICなし） |

- 本物の内角（L字の折れ曲がりなど）: 対角が空=NotThis → IC_* 表示 ✓
- 2マス幅/高さ領域: 対角が同タイル=This → base（Xアーティファクトなし） ✓
